Message field restrictions

Last updated October 8th, 2026

This document is new for the Knox cloud services 26.10 UAT.

On this tab

  • List of impacted features
  • Knox Guard console
  • Knox Guard API

As part of our commitment to strengthening product security, starting with Knox Guard 26.10, certain special characters aren’t supported in messages and can’t be entered.

Blocked characters include: < > | ~ ` ^ \ =

This restriction impacts all device actions, policies, and endpoints in the Knox Guard API with a Message input field. Configurations set prior to the 26.10 release continue to function without issue. However, creating, updating, or re-applying any policy with blocked characters returns an error.

In addition, blocked characters may be removed or modified from CSV file exports. As such, you may notice that the values in the exported file differ from the original input in the Knox Guard console. This applies even to legacy activity log entries created before this restriction was introduced. The original values stored in your policies aren’t modified.
